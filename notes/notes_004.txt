4. FINDING SURFACED BY LIVE VERIFICATION: max_tokens TOO LOW
The first end-to-end attempt failed cleanly: response.stop_reason was "max_tokens"
for agents.md at the original ceiling of 4096, caught by the notes_003.txt
_extract_text_response check exactly as designed (clear "Generation Error" dialog,
no partial or corrupt file written, controls correctly re-enabled with the error
text retained on the status line — this incidentally also live-confirmed three of
the seven notes_003.txt fixes working together under a real failure).

Consulted Anthropic's own current guidance rather than guessing a replacement
value: Claude Sonnet 5 supports up to 128,000 output tokens, but that requires
streaming to avoid HTTP timeouts; for a non-streaming call (this app does not
stream) the documented default ceiling is approximately 16,000. Raising max_tokens
does not by itself increase cost, since Anthropic bills by tokens actually
generated rather than by this ceiling.

Tried 8192 first as an intermediate step — bug_hunter.md truncated again, same
clean handling. Raised to 16000 and reran: agents.md (21 KB), bug_hunter.md
(33 KB) and enhancement_agent.md (19 KB) all generated in full, correct sizes,
each file's tail read as a complete sentence rather than a mid-thought cutoff, and
Explorer opened correctly to Desktop\Agent Outputs\Agent Scaffolder. This finding
was not present in notes_001.txt or notes_002.txt; it could only surface via an
actual live call against a real codebase, which is why both prior audits
explicitly disclosed it as an open gap ("API compatibility and reproducibility
remain unverified" / "No live request was made").
