AGENT SCAFFOLDER — NUMBERED OUTPUT INSTEAD OF OVERWRITE
Date: 11 September 2026
Report: notes_012.txt
Predecessor: notes_011.txt (batch-1 live-test checkpoint)
Author role: Feature development and UI/UX specialist

1. PURPOSE
Ship the explicit user request made mid-way through the batch-1 checkpoint:
"Rather than overwriting and amending agents.md, I'd prefer to increment
the filename with a number, saving it as agents_2.md and so on." First
release of batch 2 (1.8-1.11, per ROADMAP.md "Testing cadence").

2. DESIGN DECISION
ROADMAP.md had flagged this as needing a decision between a per-file
counter and one shared run number across all three files. The user's own
wording ("agents_2.md and so on") already answers this: per-file, not a
shared run number. No separate design round was needed - implemented
directly as stated.

3. CHANGES
- agent_scaffolder.py: new `_next_available_path(directory, filename)`
  helper (module level, next to `safe_folder_name`). Splits the filename
  into base/ext, returns the plain path if it doesn't exist yet, otherwise
  walks `_2`, `_3`, ... until it finds a free slot. Deliberately fills the
  lowest free gap rather than always incrementing past the highest number
  that ever existed (verified: creating `agents_5.md` by hand doesn't stop
  the next real write from claiming `agents_3.md` if that's still free) -
  self-healing if a numbered file is deleted, and simpler than tracking a
  separate "last used number" anywhere.
- `run_scaffolding`'s file-write loop now calls
  `_next_available_path(output_dir, name)` per file instead of always
  `os.path.join(output_dir, name)`, and collects the actual paths written
  into `written_paths` (previously the loop didn't track output paths at
  all, only the `generated` dict of name -> text).
- Completion message rebuilt from `written_paths` instead of `generated`:
  now reads e.g. "Agent scaffolding complete! (1 file: agents_2.md)\nOutput:
  ..." - naming the actual file(s) written, since they're no longer
  predictable from the checkboxes alone once numbering kicks in.
- No pruning/cap on how high the numbers go - not requested, and capping
  or auto-deleting old generations would work against the entire point of
  this feature (never destroying a working set of instructions). If disk
  usage or clutter becomes a real problem later, that's a separate,
  explicitly-scoped feature.
- APP_VERSION bumped to 1.8. CHANGELOG.md and ROADMAP.md updated.
