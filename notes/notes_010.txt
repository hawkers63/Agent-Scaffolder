1. PURPOSE
Ship the ROADMAP v1.3 item "Regenerate a single output file instead of
always running all three." Fifth and final release of the batch-1 testing
cadence (1.3-1.7 code-only; 1.8 is the reserved live-test/fix checkpoint).
This item was specifically pulled forward from the v1.3 "needs a product
decision" bucket per the user's explicit choice this session (finish v1.2,
then pull from v1.3 to round the batch out to five) - it was picked over the
other v1.3 candidates (project manager, subprocess timeout, exclusion
passthrough) because it directly reduces per-run Anthropic cost, which lines
up with the cost concern that motivated the whole batched-testing cadence.

2. CHANGES
- agent_scaffolder.py: added a "Files to generate:" label and a row of three
  `CTkCheckBox` widgets (`agents.md`, `bug_hunter.md`, `enhancement_agent.md`),
  packed left-to-right inside a transparent `CTkFrame` (still `pack()`-only
  layout - `side="left"` inside one frame, no grid/place). All three start
  checked (`.select()`), matching the previous always-generate-all-three
  default exactly, so existing behaviour is unchanged unless the user
  unchecks something.
- `self.file_checks`: dict of {filename: CTkCheckBox}, no external Tk
  BooleanVar created (state is read via `.get()`, consistent with how
  `project_menu.get()` is used elsewhere - preserves the "no Tk
  StringVar/BooleanVar" architecture invariant).
- New `_selected_agent_files()` helper returns the list of checked filenames.
- `refresh_ui_state()` extended (not parallel logic - per the "single source
  of truth" invariant) with a `files_ok` check; Generate is disabled with
  "Select at least one file to generate" if nothing is checked. Each
  checkbox's `command` calls `refresh_ui_state` so toggling updates the
  button/status immediately.
- `start_generation()`: reads `_selected_agent_files()`, bails out with the
  same "select at least one" status if empty (defensive - button is already
  disabled in that state), snapshots the selection before the worker starts
  (same UI-thread-snapshot pattern as `target_dir`/`output_dir`), disables
  all three checkboxes for the duration of the job, and passes the selection
  into the worker thread as a new `selected_files` argument.
- `run_scaffolding(self, target_dir, output_dir, selected_files)`: filters
  the existing three-entry `agents` list down to
  `[a for a in agents if a["name"] in selected_files]` right after it's
  built - one line, no restructuring of the prompt/role definitions.
  Repomix still always runs (it's the shared packaged-context input for
  whichever files are requested); only the Anthropic calls are skipped for
  unselected files, which is where the actual cost lives.
- `reset_buttons()`: re-enables all three checkboxes alongside the existing
  settings/project-menu/cancel-button resets.
- Completion message now reads "Agent scaffolding complete! (N file(s))"
  instead of always implying three, since N can now be 1-3.
- APP_VERSION bumped to 1.7. CHANGELOG.md and ROADMAP.md updated. This
  closes out batch-1 (1.3-1.7) entirely.
