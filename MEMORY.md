## What this app is
A Windows desktop utility (`agent_scaffolder.py`, single-file CustomTkinter app) that
packages a selected project with Repomix and sends it to the Anthropic API once per
selected file (checkboxes, all three checked by default, since 1.7) to generate up to
three Markdown *instruction* documents for an AI coding assistant: `agents.md`,
`bug_hunter.md`, `enhancement_agent.md`. It does not run or execute an autonomous
agent — it only writes configuration/instruction text, saved to
`%USERPROFILE%\Desktop\Agent Outputs\<project>`.

Notably self-hosting: this repo's own `agents/*.md` files were generated by this tool
and are now the dev-instructions the maintainer follows when working on the tool
itself (see `CONTRIBUTING.md`).

## Testing cadence (adopted 2026-09-11)
Real Anthropic API calls and real Repomix runs cost real money per execution.
Going forward: five code-only releases (source review + compile check, no live
call) then a live test pass, fixing whatever it finds, then repeat. Batch 1
(1.3-1.7) checkpoint ran 2026-09-11 and found **no bugs** — see
`notes/notes_011.txt`. Since nothing needed fixing, no separate bugfix version
was cut; 1.8 starts batch 2 with real feature work. If a future checkpoint
*does* find bugs, that fix work should occupy the next version number before
batch 2's five code-only releases resume. Don't skip a batch's live-test
checkpoint or extend a batch past 5 without asking — the whole point is
keeping cost predictable.

Live-test harness note for next time: drive the real `ScaffoldingApp` through
its own real `app.mainloop()`, scheduling steps via `app.after(...)` — do NOT
manually poll with `app.update()` in a loop, since that leaves the main thread
"not in the main loop" from Tcl's point of view and breaks the worker thread's
`self.after(0, ...)` marshaling (`RuntimeError: main thread is not in main
loop`). This is a harness bug, not an app bug, but it wastes a test cycle if
repeated. See `notes/notes_011.txt` §2 for the working pattern (also useful:
wrapping `anthropic.resources.messages.Messages.create` to count real calls
without changing behavior, to verify call-count claims precisely instead of
inferring them from files written).

**Second harness gotcha (2026-09-11, v1.9 attempt):** driving the real GUI to
test a `ScaffoldingError` path hung the Windows process twice - once because
`_show_error` pops a real blocking native `messagebox.showerror` dialog with
no automated way to dismiss it (patch `messagebox.showerror` to a no-op
recorder if a test needs to reach an error path), and once with the driver
process itself going "Not Responding" at the Windows message-pump level for
an undiagnosed reason even after that patch. When a mechanism (e.g.
`Popen.wait(timeout=...)` + `terminate()`/`kill()`) is already live-verified
through the GUI for one feature (Cancel, v1.4), and a new feature reuses the
exact same mechanism (the 1.9 Repomix timeout), prefer an isolated
non-Tk script proving the mechanism itself over a second live-GUI attempt -
it gets equivalent confidence without the hang risk. See `notes/notes_013.txt`.

## Architecture invariants — do not break these without an explicit request
- Single-file app (`agent_scaffolder.py`). No module split.
- CustomTkinter only; `pack()` layout only (no grid/place, no ttk, no Tk StringVar/BooleanVar).
- Segoe UI font; grey secondary text/buttons vs accent primary action.
- API key lives in Windows Credential Manager via `keyring` (service `AgentScaffolderApp`,
  account `AnthropicAPIKey`) — never JSON, never plaintext.
- Long-running work (Repomix subprocess, Anthropic calls) runs on a daemon
  `threading.Thread`, never the Tk main loop; widget updates from that thread must go
  through `self.after(0, ...)`.
- `refresh_ui_state()` is the single source of truth for button/status enablement — any
  new control should extend it rather than adding one-off enable checks.
- `_suppress_project_event` must guard every programmatic `project_menu.set(...)`.
- `_job_running` / `_cancel_requested` / `_current_process` track an in-flight
  generation end-to-end; any new control that starts, blocks on, or cancels a job
  should extend these rather than adding parallel state (added 1.3/1.4).
- `self.file_checks` (dict of filename -> `CTkCheckBox`) selects which of the three
  agent files to generate; read via `.get()`, not an external Tk BooleanVar, per the
  no-Tk-variable-bindings rule. Any new per-file toggle should extend this dict
  rather than adding separate widgets/state (added 1.7).
- Output contract: `Desktop/Agent Outputs/<project>` — do not relocate without being asked.
  Since 1.8, files there are never overwritten: first generation keeps the plain
  filename, later ones get the next free `_N` suffix per file (`_next_available_path`).
  Don't reintroduce overwrite-in-place without an explicit request.
- `projects.json` / `last_project.json` are local, gitignored, user-editable while the
  app is closed.
